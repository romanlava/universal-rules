# Подключение базы правил к проекту

Три способа, от рекомендуемого к экзотике. Во всех случаях в контекст проекта попадает
только `INDEX.md`; полные правила ИИ читает по требованию.

## Вариант A — Git submodule (рекомендуется)

Версионируемая связка: проект фиксирует конкретный коммит базы правил,
обновления — явные и обратимые. Работает в CI и на любой машине.

Подключение (пример для CRM):

```bash
cd ~/Projects/CRM
git submodule add https://github.com/romanlava/universal-rules.git design-rules
```

В `CLAUDE.md` проекта добавить блок:

```markdown
## Design & UX Rules
@design-rules/INDEX.md
Перед генерацией или ревью любого UI: найди в индексе правила с совпадающими
триггерами и прочитай их полные версии из design-rules/rules/.
```

Обновление до свежих правил:

```bash
git submodule update --remote design-rules
git add design-rules && git commit -m "chore: bump design rules"
```

Клонирование проекта на новой машине: `git clone --recurse-submodules <crm-url>`.

**Плюсы:** версия правил зафиксирована в истории проекта; можно откатить; CI видит правила.
**Минусы:** привычная submodule-рутина (не забывать `--recurse-submodules`).

## Вариант B — Абсолютный @import (быстрый старт, одна машина)

Ничего не устанавливается: проект просто ссылается на локальный клон.

В `CLAUDE.md` проекта:

```markdown
## Design & UX Rules
@~/Projects/Universal Rules/INDEX.md
Перед генерацией или ревью любого UI: найди в индексе правила с совпадающими
триггерами и прочитай их полные версии из ~/Projects/Universal Rules/rules/.
```

**Плюсы:** ноль настройки, правки в базе видны во всех проектах мгновенно.
**Минусы:** не работает у коллег/в CI (путь локальный); нет фиксации версии —
изменение базы молча меняет поведение всех проектов.

## Вариант C — Claude Code plugin

Репозиторий уже содержит `.claude-plugin/` (манифест + marketplace) и skill
`ux-architect`. Установка:

```bash
claude plugin marketplace add romanlava/universal-rules
```

затем `/plugin install universal-design-rules` в интерактивной сессии.
Skill автоматически активируется на UI-задачах во всех проектах.

**Плюсы:** самый «родной» для Claude Code способ, скилл сам знает, когда включаться.
**Минусы:** обновления — через переустановку/обновление плагина; чуть больше движущихся частей.

## Что выбрать

* Соло-разработка на одной машине, хочется мгновенных обновлений → **B**.
* Проект живёт в CI, работа с нескольких машин или в команде → **A**.
* Много проектов и хочется автоподхвата без правки CLAUDE.md каждого → **C**.

Варианты совместимы: можно начать с B и позже перейти на A без изменения самой базы.

## Правило разделения

В этот репозиторий попадает только универсальное. Проектное — цвета бренда, конкретные
компоненты, доменные термины CRM — остаётся в CLAUDE.md проекта. Если правило хочется
написать «только для CRM», ему здесь не место.
